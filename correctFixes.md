## Data Preparation (Run Once Per Task)

### 1. Persistent Object Gaussian Splat (POGS) Setup
Because RLBench uses domain randomization (the drawer spawns in different locations), a single "shared" NeRF is often insufficient for precise tracking.

**Recommended Workflow for New Episodes:**
1. **Train Episode-Specific NeRF**: Train a Gaussian Splat on the first frame/capture of the specific episode you want to generate.
2. **Export Clusters**: Use the POGS viewer (\`pogs.py\`) to segment the object (e.g., drawer handle) and export \`clusters.npy\`.
3. **Generate ACT Episode**:
   \`\`\`bash
   # Run the tracking and dataset generation script
   ./test_episode_0.sh
   \`\`\`

### 2. Implementation Fixes (Applied)

#### Cluster Path Fallback
The \`pogs/tracking/optim.py\` was patched to support loading \`clusters.npy\` from multiple locations to prevent \`FileNotFoundError\` when the viewer exports to a different subfolder than the trainer expects.
- Checks: \`outputs/<config_name>/clusters.npy\`
- Falls back to: \`outputs/<dataset_name>/clusters.npy\`

#### Tracking Camera Fix
The POGS tracking logic was updated to use the **Front Camera** (\`front_rgb\`) for pose optimization, as the **Wrist Camera** is used primarily for the initial static scene capture. This prevents "Object left ROI" errors during tracking.

#### Robust Dataset Serialization
\`pogs/scripts/generate_pogs_act_dataset.py\` was updated with:
- **Atomic Saves**: Prevents corrupted \`.pkl\` files if the script crashes.
- **Resume Support**: Automatically skips episodes that already have a valid \`.pkl\` file.
